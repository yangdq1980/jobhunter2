# 01 · 需求分析

> 项目代号：**jobhunter2** —— 基于 Docker n8n 的职位采集 → 飞书 → Ollama 评估 → 看板 四步自动化流水线
> 文档版本：v1.0 ｜ 创建日期：2026-10-14 ｜ 负责人：唐小臧（产品/运维），孙小猴（实现）

---

## 1. 项目背景与目标

唐小臧老板当前重点求职方向为 **广州黄埔区 AI / 云计算 / 解决方案架构师** 岗位。为提升求职效率、避免遗漏高价值岗位，需要一套**可定时运行、自动采集、自动评估、自动归档与可视化**的流水线。

本项目的目标不是从零造轮子，而是**复用已有且验证过的环境与配置**（见第 4 节），把四个能力编排成一条 n8n 工作流：

| 步骤 | 能力 | 产出 |
|------|------|------|
| 第一步 | 智联招聘按关键词搜索并抽取字段 | 结构化职位数据（公司/职位/薪资/地点/描述/链接） |
| 第二步 | 写入飞书多维表格 | 持久化、可协作的职位库 |
| 第三步 | 本地 Ollama LLM 综合评估并发送飞书群 | 每条职位的评估简报 + 群内推送 |
| 第四步 | 看板统计与可视化 | 匹配度/城市/学历分布、趋势图、明细表 |

---

## 2. 四步详细需求

### 2.1 第一步：智联招聘采集（Step-1 抓取）
- **输入**：关键词列表（默认 `["AI解决方案架构师","云计算架构师","解决方案架构师"]`）、城市（默认 `广州`）、最大翻页数、单关键词最大职位数。
- **抽取字段（必须完整）**：
  - 公司名 `company_name`
  - 职位名 `title`
  - 详细描述 `description`（JD 正文，需进入详情页抓取）
  - 原始链接 `job_url`
  - 薪水范围 `salary_raw`（如「1.5-3万/月」）
  - 工作地点 `city` + `district`
  - 经验 `experience`、学历 `education`
- **反爬约束**：智联为 React 单页 + 登录墙 + 滑块验证。方案：用 Playwright 真实浏览器，复用已登录浏览器 Profile 规避登录墙；被拦时返回 `warning` 标记交由人工补采，**不自动解验证码**。
- **交付形态（路线 B 已调整）**：复用既有 jobhunter 后端（`G:/workbuddy/workspace/jobhunterforai`，FastAPI，`:8911`）的 `/crawl/zhilian` 成熟爬虫，n8n 通过 `host.docker.internal:8911` 调用；不再独立维护 `scraper/:7800` 微服务。

### 2.2 第二步：飞书多维表格（Step-2 落库）
- 字段与第一步、第三步严格对齐，目标表字段（飞书多维表格）：
  `平台 / 职位名 / 公司名 / 薪资范围 / 工作地点 / 经验 / 学历 / 描述 / 原始链接 / 评估结论 / 匹配度 / 抓取时间`
- 写入方式（路线 B）：n8n「写飞书多维表格」节点 `POST /sync/feishu/push` 调**后端代理**，由后端 `feishu_client.py` 走 `bitable/v1` 写入；飞书鉴权在后端 `.env`，n8n 零飞书凭据（绕开 21001）。

### 2.3 第三步：Ollama 评估 + 飞书群推送（Step-3 评估触达）
- **评估模型**：本地 Ollama `qwen3:8b`（已确认本机已装，4983MB）。
- **评估维度**：技术方向判断、学历要求、经验要求、与「广州黄埔 AI/云计算/解决方案架构师」目标的匹配度（高/中/低）+ 一句话理由、给求职者行动建议。
- **推送**：评估简报逐条发送至指定飞书群（`im/v1/messages`，`receive_id_type=chat_id`）。

### 2.4 第四步：看板（Step-4 可视化）
- 职位数据 + 评估结论 + 匹配度 落本地 MySQL（复用 n8nwp 的 MySQL，库 `n8n`）。
- 提供统计接口与可视化页面：累计职位数、高匹配数、匹配度分布、城市分布、学历分布、近 14 日趋势、职位明细。
