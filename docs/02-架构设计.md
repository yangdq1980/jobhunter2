## 1. 整体架构

```
┌────────────┐   关键词/城市    ┌──────────────────────────┐
│  n8n 工作流 │ ───HTTP POST──▶ │  既有 jobhunter 后端(宿主机)    │
│ (n8nwp-n8n)│                  │  :8911 /crawl/zhilian (Playwright)│
│  四步编排   │ ◀──{platform,crawled}── │                          │
└─────┬──────┘                  └──────────────────────────┘
      │
      ├─▶ ① 获取飞书 tenant_access_token (open.feishu.cn)
      │
      ├─▶ ② POST /sync/feishu/push（走后端代理，绕开 21001）
      │        → 后端读 SQLite → upsert 飞书多维表（控制面板）
      │
      ├─▶ ③ Ollama 评估 (host.docker.internal:11434, qwen3:8b)
      │        │
      │        ├─▶ 组装简报 → 发飞书群 (im/v1/messages)
      │        └─▶ 组装负载 → 落看板
      │
      └─▶ ④ 落看板数据 → jobhunter2-dashboard:8100/api/jobs/ingest
                               │
                               ▼
                        MySQL(n8n库).jobs_pipeline
                               │
                               ▼
                   /jobs 可视化页面 (Chart.js)
```

**关键网络关系（同一 Docker 网络 `n8nwp_n8nwp-net`）**
- n8n 容器通过 `host.docker.internal`（host-gateway）访问宿主机上的 Ollama(:11434) 与 jobhunter 后端(:8911)。
- n8n 通过服务名 `jobhunter2-dashboard:8100` 访问看板容器（同网络 Docker DNS 解析，已验证可达）。
- 飞书 API 为外网地址，n8n 出网正常。

## 2. 组件职责与接口契约

### 2.1 既有 jobhunter 后端（`/crawl/zhilian`）
- **类型**：既有 FastAPI 服务（`jobhunterforai`），宿主机运行，监听 `:8911`（n8n 经 `host.docker.internal:8911` 调用）。
- **抓取入口**：`POST /crawl/zhilian`
  - 查询参数：`keywords`（逗号分隔，可空；空则用后端 config）、`max_jobs`（默认 60）。
  - 响应：`{"platform":"zhilian","crawled":N,"new":M,"warning":null,"note":"已评分并写入 SQLite；非黄埔职位在采集层已过滤。"}`
  - ⚠️ 不返回职位 JSON，职位落后端 SQLite（后端 `scorer` 已自带评分/命中判定）；评估前需 `GET /jobs` 取数。
- **取数入口**：`GET /jobs?matched=true&limit=200` → 返回 `job_to_dict` 数组（字段含 `title/company_name/salary_raw/city/district/experience/education/description/job_url/crawled_at/score/matched/...`）。
- **飞书写入（代理）**：`POST /sync/feishu/push`（无 body）→ `{"ok":true,"pushed":N,"created":N,"updated":N}`。飞书鉴权在后端 `feishu_client.py`，凭据来自后端 `.env`，**n8n 零飞书凭据**。
- **反爬**：复用系统 Chrome Profile 登录态（由后端管理）。

### 2.2 n8n 工作流（`n8n-workflows/job-pipeline.json`）
13 个节点 / 13 条连接（路线 B），节点清单：

| # | 节点 | 类型 | 职责 |
|---|------|------|------|
| 1 | 手动触发 | manualTrigger | 手动试运行 |
| 2 | 每日定时触发 | scheduleTrigger | 每天 09:00 |
| 3 | 配置 | set | keywords 数组 / maxJobs |
| 4 | 获取飞书Token | httpRequest | 取 tenant_access_token（供发群） |
| 5 | 调用智联爬虫 | httpRequest | → :8911/crawl/zhilian（无 body，关键词走 query） |
| 6 | 拉取职位 | httpRequest | → :8911/jobs?matched=true（取命中职位供评估） |
| 7 | 展开职位 | code | 扁平化为单条职位 |
| 8 | Ollama评估 | ollama | qwen3:8b 生成简报 |
| 9 | 组装负载 | code | 解析匹配度(高/中/低)，生成群消息正文 |
| 10 | 写飞书多维表格 | httpRequest | → :8911/sync/feishu/push（后端代理，绕开 21001） |
| 11 | 落看板数据 | httpRequest | → jobhunter2-dashboard:8100/api/jobs/ingest |
| 12 | 筛选高匹配 | code | 仅保留 高/中 匹配 |
| 13 | 发飞书群 | httpRequest | im/v1/messages（仅高/中匹配） |

- **变量注入**：飞书凭证与 Bitable 目标从 n8n Variables（`$vars.xxx`）读取，已写入库并归属个人项目 `u9V5K0IVNGRyDOLk`。
  - `feishuAppId` / `feishuAppSecret`（已填，供「获取飞书Token」）
  - `feishuGroupChatId`（已填，飞书群 chat_id）
  - ⚠️ 不再需要 `feishuBitableAppToken` / `feishuBitableTableId`（飞书写入改走后端 `/sync/feishu/push`，凭据在后端 `.env`）

### 2.3 看板服务（`dashboard/`）
- **类型**：FastAPI（基于本地镜像 `n8nwp-dashboard:latest`，零联网拉取），容器 `jobhunter2-dashboard:8100`。
- **接口**：
  - `POST /api/jobs/ingest`：接收单条或批量职位，幂等写入 `jobs_pipeline`（唯一键 `platform+company_name+title+city`）。
  - `GET /api/jobs/stats`：匹配度/城市/学历/公司分布 + 近 14 日趋势 + 总计。
  - `GET /api/jobs`：职位明细列表。
  - `GET /jobs`：Chart.js 可视化页面。
- **建表**：启动时 `CREATE TABLE IF NOT EXISTS jobs_pipeline`（幂等）。

### 2.4 飞书多维表格（Step-2）
- 通过 `bitable/v1/apps/{app_token}/tables/{table_id}/records/batch_create` 写入。
- 字段映射（n8n「组装负载」节点生成 `bitable_fields`）：

| 飞书字段 | 来源 |
|----------|------|
| 平台 | `platform` |
| 职位名 | `title` |
| 公司名 | `company_name` |
| 薪资范围 | `salary_raw` |
| 工作地点 | `city`+`district` |
| 经验 / 学历 | `experience` / `education` |
| 描述 | `description`(截断4000) |
| 原始链接 | `{text:"查看职位", link:job_url}` |
| 评估结论 | Ollama 输出(截断2000) |
| 匹配度 | 从评估文本解析 高/中/低 |
| 抓取时间 | `crawled_at` 毫秒戳 |

## 3. 关键设计决策

1. **爬虫微服务化**：智联反爬严重、需真实浏览器与登录态，不适合在 n8n 节点内执行。拆成宿主机微服务，n8n 仅做 HTTP 调用，解耦且易独立调试。
2. **变量集中注入**：飞书凭证与 Bitable 目标全部走 n8n Variables，工作流 JSON 不落明文密钥，符合安全约束。
3. **看板独立容器**：新建 `jobhunter2-dashboard` 容器（而非改动既有 AI 看板），使 jobhunter2 项目自洽、便于 GitHub 管理，且镜像基于本地已有镜像零联网构建。
4. **幂等写入**：看板 `ingest` 用 `ON DUPLICATE KEY UPDATE`，重复推送不脏数据。
5. **工作流非激活待启用**：导入后保持 `active=0`，待 Bitable 变量填好、爬虫启动后由用户在 UI 一键激活，避免每日定时误跑报错。
